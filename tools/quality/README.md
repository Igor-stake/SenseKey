# Проверка качества SenseKey

Цель этого этапа - осмысленные продолжения, а не минимальная задержка. Биография и предпочтения пока не входят в запросы предсказаний. Их заполнение не исправляет слабую модель.

## Модель на телефоне

Для следующего сравнения выбран **Qwen3.5-9B, Q4_K_M**: текстовые веса из репозитория Unsloth, около **5,68 ГБ** на диске. Это кандидат для проверки качества, а не обещание, что любой ответ станет правильным. Вариант на 4B занимает около 2,74 ГБ и также доступен в скрипте.

Модель устанавливается отдельно от APK. Старую модель удалять не нужно.

1. Установи новый APK SenseKey DEV поверх предыдущего.
2. Открой **Termux**. Если там работает старый llama-server, нажми **CTRL**, затем **C**. Должна появиться строка с `$`.
3. Вставь следующую команду целиком и нажми **Enter**. Дождись возвращения строки с `$`:

```bash
curl -fL --retry 3 -o ~/sensekey-model.sh https://raw.githubusercontent.com/Igor-stake/SenseKey/prealpha-context-fixes/tools/quality/run-model-termux.sh
```

4. Вставь следующую команду и нажми **Enter**:

```bash
bash ~/sensekey-model.sh 9b
```

Скрипт скачает модель, проверит SHA-256, запустит локальный сервер и один раз подготовит общий промпт клавиатуры. Первая загрузка скачивает несколько гигабайт; проценты относятся к скачиванию, а не генерации ответа. При повторном запуске скачанная модель используется снова. Дождись конечной строки готовности: **`SENSEKEY READY`**. Строка `listening` появляется раньше, до подготовки промпта.

Для варианта на 4B сначала останови сервер сочетанием CTRL и C, затем выполни `bash ~/sensekey-model.sh 4b`. В обоих случаях адрес сервера и его имя `sensekey` сохраняются. Если в настройках SenseKey вручную указана другая модель, оставь поле модели пустым для автоматического определения либо укажи `sensekey`.

Не закрывай сеанс Termux после появления строки готовности. Вернись в переписку и проверь предложения сначала на простом вопросе, затем на отказе и сообщении с отрицанием. Клавиатура предлагает текст, но не отправляет сообщения.

Если сервер сообщает о неизвестной архитектуре модели, обнови пакет llama-cpp через `pkg upgrade`, затем повтори запуск скрипта. Если появляется ошибка загрузки модели или нехватки памяти, её текст важнее догадок по интерфейсу; вариант на 4B требует меньше памяти. Запуск этих весов и задержка на телефоне должны быть проверены отдельно: настольные измерения этого не подтверждают.

## Что изменилось в запросе

- Модель получает конкретную задачу: предложить следующее сообщение человека, сохранив набранное начало буквально.
- Формат ответа - JSON с целым сообщением. Приложение проверяет начало и вставляет только оставшееся продолжение.
- Текущий экран выделен отдельно от сохранённых фрагментов, порядок которых может быть неизвестен.
- Примеры показывают согласие, отказ, использование известного времени, благодарность и отказ от выдумывания личных фактов.
- Пустые, обрезанные, устаревшие и копирующие историю ответы не показываются. Дополнительно скрываются новые числа и некоторые календарные детали, которых нет в контексте или черновике. Это ограниченная проверка, а не понимание всех фактов.

Одной фразы «не выдумывай» оказалось недостаточно. В частности, проверка календарных деталей не обнаруживает все выдуманные причины, отношения или намерения. Авторы сообщений и цитаты также не всегда распознаются надёжно.

## Воспроизводимая проверка

`cases.json` и `holdout.json` содержат 28 вымышленных ситуаций, использованных при разработке. После просмотра результатов и изменения правил `holdout.json` больше не считается независимой проверкой. `validation.json` содержит отдельные восемь примеров для проверки зафиксированного варианта. Личные переписки не используются.

Хостовый инструмент компилирует настоящие `SenseCompletionClient` и `SenseCompletionQuality`, экспортирует запросы и применяет тот же разбор ответа. Только объект состояния редактора и Android-логирование заменены маленькими заглушками. Отдельные тесты приложения проверяют настоящий редактор, свежесть контекста и Android runtime.

```bash
python3 tools/quality/evaluate.py --server /path/to/llama-server --model /path/to/model.gguf --output /tmp/sensekey-quality
```

Для независимых примеров добавь `--cases tools/quality/validation.json`. Нужны JDK и Python 3.11+. Версия org.json фиксирована и проверяется по SHA-256. Итоги сохраняют точные запросы, сырые ответы, контрольную сумму исходника и модели. Seed 42 используется только для воспроизводимости проверки; приложение его не фиксирует.

Правильность оценивается по смысловому критерию `check` для каждого примера, а не только по прохождению строкового фильтра. Пустое предложение засчитывается как правильное лишь там, где оно действительно требуется. Время на CPU этого окружения не является задержкой на Galaxy Z Fold.

Источники моделей: [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B), [GGUF Unsloth](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF). Зафиксированные ревизии и контрольные суммы находятся в скрипте запуска и результатах проверки.

## Эксперимент с Bonsai 2 27B

Следующий кандидат - **Ternary Bonsai 2 27B, PQ2_0** от PrismML. Текстовые веса занимают **7 206 168 928 байт**, около 7,21 ГБ. Более компактный PTQ1_0 занимает **5 946 648 928 байт**, около 5,95 ГБ, но холодная обработка промпта в нашей проверке была значительно медленнее. Это другая модель, чем первая бинарная Bonsai на 3,9 ГБ. Для Bonsai 2 нужен специальный движок Prism с преобразованиями Hadamard; установленный пакет `llama-cpp` не заменяется.

В Termux:

1. Останови работающий сервер: **CTRL**, затем **C**. Дождись строки с `$`.
2. Скачай скрипт и дождись возвращения `$`:

```bash
curl -fL --retry 3 -o ~/sensekey-bonsai.sh https://raw.githubusercontent.com/Igor-stake/SenseKey/prealpha-context-fixes/tools/quality/run-bonsai-termux.sh
```

3. Запусти:

```bash
bash ~/sensekey-bonsai.sh
```

Скрипт скачает официальный Android arm64 движок на 78 МБ и модель, проверит SHA-256 файлов и запустит сервер на **127.0.0.1:8080** с именем **sensekey**. Затем прогреет общую инструкцию клавиатуры без данных телефона. Дождись строки **`SENSEKEY READY`**: до неё первый прогрев может занимать несколько минут. Запуск повторяется той же командой. Незавершённое скачивание продолжается с прежнего места. Понадобится около 9 ГБ свободного места сверх уже установленных моделей; старые модели остаются на телефоне. Для компактного варианта укажи `bash ~/sensekey-bonsai.sh ptq`; это компромисс по памяти, а не способ ускорения.

Новый APK для замены модели не нужен. В настройках продолжений оставь поле модели пустым либо укажи `sensekey`, адрес - `http://127.0.0.1:8080`. Не переключайся в чат до строки `SENSEKEY READY`. `status: ok` проверяет доступность сервера, но не качество и скорость генерации.

**Это CPU-эксперимент.** Официальный Android-архив этой ревизии не содержит Vulkan-бэкенда. Поддержка формата в Vulkan-исходниках не доказывает ускорение на Fold. Скорость iPhone/Metal из новости о первой Bonsai к этому запуску не относится. Помимо весов нужны память для состояния модели и рабочих буферов. Если Android завершает процесс или модель не загружается, сохрани текст ошибки; не увеличивай контекст наугад.

В скрипте явно отключены рассуждения и ограничены оба размера батча до 16 (в обновлённом запуске Qwen - до 64). Это даёт серверу возможность обрабатывать отмену между меньшими порциями промпта; уменьшение только `ubatch` не ограничивает весь вызов decode. Ограничен также кэш сохранённых состояний - 128 МиБ. Такие настройки не обещают более быстрый полный ответ: меньший батч может снизить скорость обработки контекста. Префикс в активном слоте продолжает использоваться повторно.

Прогрев переносит дорогую обработку постоянной инструкции на запуск сервера, до печати сообщения. В `warmup.json` находятся настоящие инструкции/вымышленные примеры приложения и пустой контекст/черновик. Текст из телефона не запрашивается. Это не ускоряет сами операции модели и не сохраняет кэш после остановки процесса. Смена инструкции, переполненный контекст и особенности бэкенда могут потребовать новой обработки. Восьмёрка простых проверочных диалогов с PQ2_0 дала шесть полезных ответов и два уместных отказа; результаты и ограничения записаны в `RESULTS.md`.

Если доступна команда `termux-wake-lock`, скрипт удерживает блокировку сна на время работы и освобождает её при выходе. Для Termux в Android выбери **Настройки → Приложения → Termux → Батарея → Без ограничений** (название зависит от One UI). Блокировка сна не отменяет ограничения Android на работу приложения в фоне.

Сначала проверь один запрос, не печатая дальше и не переключая приложение до результата. Потом проверь обычный непрерывный набор, удаление и переход между чатами. Сравнивай полезность текста и полное ожидание; серверные `prompt_ms` и `predicted_ms` показывают только часть задержки. Обе модели получают одну и ту же задачу и один формат данных.

Первичные источники: [веса Bonsai 2](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf), [зафиксированный релиз Prism](https://github.com/PrismML-Eng/llama.cpp/releases/tag/prism-b10754-2459f68), [поддержка бэкендов](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/BACKEND-SUPPORT.md).
